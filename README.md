# CoJu — 年轻人聚会规划助手（修复版）

一起出发，公平相聚。输入每位成员的出发地、预算和口味，CoJu 对比通勤公平、预算、评分和偏好，透明打分后推荐这次聚会最合适的餐厅、每人的公交路线，以及餐厅附近的饭后玩乐。

## 运行

推荐 Python 3.12。Windows 解压后双击 `start.bat`，首次运行会安装依赖，然后打开本地网页。 若已有 Python 环境，也可运行：

```text
python -m pip install -r requirements.txt
python -m streamlit run app.py

```

本地地址：[http://localhost:8501](http://localhost:8501) 。需要让启动窗口保持运行。此地址不是公网分享链接。

## 数据模式

- **离线示例**（默认）：使用固定的 3 位上海成员和模拟数据，仅供体验，成员不可增减。
- **真实地点查询**：在左侧输入自己的高德 Web 服务 Key → 填写各成员具体地点 → 点击“核对出发地点” → 逐人选择正确地点并勾选确认 → 点击“生成聚会方案”。- 成员可**逐个增删**（➕ 添加成员 / ➖ 删除该成员，2–8 人）。
- Key 仅在本次会话使用，不写入源代码或下载文件；程序仅将所需地点发送给高德服务。

## 使用要点

- **菜系**：先选分类，再选具体菜系；多个菜系表示任一均可，不选表示不限。仅推荐匹配的菜系，不用其他菜系凑数；未选火锅时不会混入火锅店。
- **出行方式**：公共交通优先模式不会改成驾车。短途无公交时可查询步行/骑行；也可指定仅公共交通、步行或骑行。
- **饭后玩乐**：围绕每家推荐餐厅就近搜索所选玩乐类型，搜索范围按需从约 1.5 公里逐级扩大至 5 公里；某类查不到不影响其他类型。
- **重新生成**：修改地点、预算、菜系等条件后需重新生成；只调整推荐权重时使用已取得的候选重新排序，不再请求高德。
- 真实查询会调用多次接口。调试额度有限时，先用离线示例体验页面，避免反复生成。

## 文件

- `app.py`：界面、地点核对、成员增删、状态更新和地图
- `amap.py`：高德接口与验证；无驾车兜底，失败显式报错不伪造数据
- `cuisines.py`：菜系分类、同义词、严格菜系匹配
- `scoring.py`：可解释评分与重新排序
- `llm.py`：基于真实结果的规则文案，以及暂未接入界面的可选自然语言解析函数
- `mock_data.py`：显式标注的离线示例数据（3 位上海成员）
- `requirements.txt` / `requirements-lock.txt`：依赖清单与本次验证的锁定版本
- `Fixing Instruction.md`：修改点与验证边界
- `Demo_Day_Script_Revised_EN.md`：与当前功能一致的英文演示稿

## 相对上一版本的修复

1. **饭后玩乐偶尔搜不到**：搜索半径由固定 1 公里改为 1.5→3→5 公里逐级扩大，每类多取候选，单类型请求失败不再中断其余类型。
2. **成员可逐个增删**：真实查询模式下每位成员旁提供删除按钮，底部提供添加按钮（2–8 人）。

## 说明

- 当前为同城规划 MVP，每次最多对约 12 家附近餐厅计算成员路线，不代表“全城最优”。
- 匹配依赖第三方商家标签，标签缺失会保守排除；没有结果不等于当地没有该菜系。
- 界面使用表单与规则文案；自然语言解析函数仍是扩展入口，未接入当前界面。路线使用高德 Web API，未接入 MCP。
